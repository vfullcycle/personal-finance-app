## Schema สุดท้าย — `budget_items` (migration `20260728120000_budget_items_merge.sql` + fix `20260728130000`)

| field | ค่า |
|---|---|
| `name` | ชื่อรายการ, **optional** — ไม่กรอก = fallback ไปใช้ชื่อบัญชีตอนแสดงผล |
| `account_id` | FK `accounts` |
| `direction` | `outflow` (จ่ายออก) \| `inflow` (รับเข้า) \| `transfer_to_asset` (โยกเข้าสินทรัพย์) — เก็บเป็น field จริงเสมอ เลือกก่อนในฟอร์ม (ปุ่มใหญ่ 3 ปุ่ม) แล้วกรองดรอปดาวน์บัญชีให้ตรง type — ไม่บังคับ `cashflow_class=savings` สำหรับ transfer_to_asset (เลือกกฎที่กว้างกว่าของชั้น B เดิม ยืดหยุ่นกว่า) |
| `frequency` | `monthly`\|`quarterly`\|`semiannual`\|`annual`\|`onetime` (5 แบบ) — `monthly` ลงยอดทุกเดือน (แทนที่ "period=month" เดิม), ความถี่อื่นลงเป็นก้อนเดียวตามรอบ **ไม่เฉลี่ยเป็นรายเดือนอีกต่อไป** (ตัด concept "ต่อปีแบบเฉลี่ยเรียบ" ของชั้น A เดิมทิ้งทั้งหมด — เป็นต้นตอความกำกวมที่ทำให้ตัดสินใจรวมตาราง) |
| `start_date` | วันที่ (ไม่ nullable) — **เดือน**ของวันนี้คือเดือนที่ตกงวดของความถี่ราย 3/6/12 เดือน (ไม่มีฟิลด์ `start_month` แยกอีกต่อไป) และเป็นฐานคำนวณ growth (`beYear - ปีของ start_date`) |
| `end_date` | วันที่ nullable — **ว่าง = ไม่มีกำหนดจบ** (พฤติกรรมแบบชั้น A เดิม) มีค่า = มีกำหนดจบ (แบบชั้น B เดิม) ไม่บังคับสำหรับ `onetime` (occurrence เช็คแค่เดือน/ปีของ start_date ตรงกันพอ) |
| `amount_per_occurrence_satang` | ต่อครั้งเสมอ (ไม่ใช่ยอดรวม, ไม่มีการหาร 12 อัตโนมัติอีกต่อไป) |
| `growth_percent_per_year` | default 0 — นับปีที่ผ่านไปจาก **ปีของ start_date ของรายการนั้นเอง** เสมอ (กฎเดียวทั้งระบบ ตัดกฎแยกของชั้น A เดิมที่นับจากปีของ projection โดยรวม) |
| `is_active` | เปิด/ปิดโดยไม่ต้องลบ |

Trigger `enforce_budget_items_account_consistency` บังคับ `direction` ↔ `account.type_id` ตรงกันเสมอที่ชั้น DB — **หนี้ที่ตั้งค่าเงินกู้ครบแล้ว (`loanAmortization.ts`, C3)** ไม่มีตัวเลือกในฟอร์มเลย (ไม่มี liability ในดรอปดาวน์ทุก direction) เว้นไว้ให้ projection ดึง amortization schedule มาใช้อัตโนมัติ

## UX

หน้า `/budget` (nav ใหม่ "งบประมาณ" 🎯) 2 แท็บ: **รายการงบประมาณ** / **คาดการณ์**

- รายการงบประมาณ: list การ์ดสไตล์เดียวกับ `/transactions` (`.item-row` ไอคอน +/- สีบอกทิศทาง) + ปุ่ม "+ เพิ่มรายการ" + ปุ่ม "ทำซ้ำ" ต่อรายการ (nested span + stopPropagation, pattern เดียวกับ `/transactions` v1.1) → dialog: เลือก**ทิศทาง**ก่อน (ปุ่มใหญ่ 3 ปุ่ม) → หมวด (กรองตาม type) → ความถี่ → จำนวนเงิน → วันที่เริ่ม → วันที่สิ้นสุด (checkbox "ไม่มีกำหนดจบ" ค่าเริ่มต้นติ๊กไว้, ซ่อนทั้งหมดถ้าเลือกความถี่ `onetime`) → ตัวเลือกเพิ่มเติม: ชื่อรายการ (optional), growth%, ใช้งานอยู่
- คาดการณ์: วันที่ปิดบัญชี, N ปี, M ปีแรกรายเดือน, โหมดตัดปี, การ์ดสรุป, กราฟ net worth, ตารางรายเดือน(M ปีแรก)/รายปี(ที่เหลือ) — ดูรายละเอียดหัวข้อ Projection Engine ด้านล่าง

### บั๊กที่เจอระหว่าง UAT + แก้แล้ว
- **หมวดหายตอนเปิด edit dialog**: `useEffect` ที่เคลียร์ `accountId` เมื่อทิศทางไม่ตรงบัญชี ยิงตอน component mount ก่อน `accounts` โหลดเสร็จ (ตอนนั้น filtered list ว่างชั่วคราว เข้าใจผิดว่าบัญชีเดิมไม่ตรง type) แก้ด้วย ref เก็บทิศทางก่อนหน้า เคลียร์เฉพาะตอนวี "เปลี่ยนทิศทางเอง" จริงๆ ไม่ใช่ตอน mount/โหลดข้อมูลครั้งแรก
- **race condition ต่อเนื่อง**: ถ้ากด "บันทึก" เร็วเกินไปก่อน `accounts` โหลดเสร็จ (หน้าต่างเวลาแคบ) ปุ่มจะกดไม่ติดแบบเงียบๆ (native HTML validation บล็อกก่อนถึง JS) — เพิ่ม guard ปิดปุ่ม "บันทึก" + โชว์ "กำลังโหลดหมวด..." ระหว่างรอ

## Projection Engine (ช่วง 2)

### Input (แท็บ "คาดการณ์")
| ช่อง | ค่า |
|---|---|
| วันที่ปิดบัญชี | date picker, default = วันนี้ — จุดเริ่มต้น projection (เดือนถัดไปเป็นเดือนแรกที่คาดการณ์) |
| N — ระยะรวม (ปี) | number input |
| M — จำนวนปีแรกที่แสดงรายเดือน | number input, M ≤ N |
| โหมดตัดปี | ปีปฏิทิน (default) \| เต็มปีจากวันปิด |

### ฐานคำนวณ = `budget_items` เท่านั้น (ไม่รวม `recurring_transactions` จริงจาก M4)
ตาม REQUIREMENTS §5.2 — รายการประจำจริงที่ auto-post เข้า ledger ไม่ถูกดึงเข้า projection ถ้าอยากให้ projection เห็นต้องกรอกซ้ำเป็นรายการ `budget_items`

### หนี้ที่ตั้งค่าเงินกู้ครบ → ดึงอัตโนมัติจาก `loanAmortization.ts`
คำนวณตารางผ่อนชำระ (เงินต้น/ดอกเบี้ยต่องวด) ของทุกบัญชีเงินกู้ที่ตั้งค่าครบ ตั้งแต่วันนี้จนครบสัญญาหรือจนสุด N ปี แสดงแยกคอลัมน์ "เงินต้นผ่อนหนี้"/"ดอกเบี้ยเงินกู้" — **ไม่รวมดอกเบี้ยเข้าคอลัมน์ "จ่ายออก"** (กันงงว่านับซ้ำ แม้ในการคำนวณ net worth/cash flow จริงจะรวมดอกเบี้ยอยู่ครบ)

### Growth compounding
นับจากปีของ `start_date` ของแต่ละรายการเอง (`beYear - startBEYear`) — ปีที่รายการเริ่ม = อัตราฐาน (ยังไม่คูณ growth) กฎเดียวทั้งระบบหลังรวมตาราง

### ผูก tax engine ต่อปี (พ.ศ.)
1. รวมรายได้ที่ต้องเสียภาษีของปีนั้น (รายการ `direction=inflow` ที่ผูกบัญชีรายได้ `taxable=true`) แยกตาม 40(1)-(8)
2. เรียก `calculateTaxReturn` (C6) — ค่าลดหย่อน = เฉพาะรายการที่วีติ๊ก **"ใช้ในงบประมาณ"** ในหน้า `/tax` (ดูหัวข้อถัดไป) คงที่ตลอดทุกปีคาดการณ์
3. ปีที่เกิน config จริง (มีถึง 2568/2569 เท่านั้น) → **extrapolate ใช้ config ปีล่าสุดซ้ำ** + banner เตือนต่อปีที่ได้รับผลกระทบ
4. ได้ "อัตราหลังหักภาษี" ของปีนั้น (after-tax ÷ pre-tax เฉพาะส่วนรายได้ที่ต้องเสียภาษี) คูณกลับเข้ารายเดือนในปีเดียวกัน (กระจายภาษีเฉลี่ยตามสัดส่วนรายเดือน ไม่ได้จำลองจังหวะหัก ณ ที่จ่ายจริง) — รายได้ที่ไม่ต้องเสียภาษี (taxable=false) ผ่านเข้า inflow เต็มจำนวนไม่ถูกหัก

### ค่าลดหย่อนสำหรับ projection — เลือกเองต่อรายการ (ตกลงเพิ่มระหว่างแชต)
เดิมออกแบบให้ดึงค่าลดหย่อนปีล่าสุดทั้งหมดมาใช้อัตโนมัติ — วีทักว่าบางรายการเป็นยอดเฉพาะปีนั้นจริงๆ (เช่น ซื้อ RMF/SSF ก้อนพิเศษปีเดียว) ไม่ควรถูกลากไปทุกปีในอนาคต จึงเปลี่ยนเป็น:
- Migration `20260727090000_tax_deduction_use_in_projection.sql` เพิ่มคอลัมน์ `use_in_projection boolean default false` ใน `tax_return_deductions`
- หน้า `/tax` แท็บ "ค่าลดหย่อน" (`DeductionsTab.tsx`) เพิ่ม checkbox "ใช้ค่านี้ในงบประมาณด้วย" ต่อรายการ (เฉพาะ `calc_type='user_amount'`)
- Header (คู่สมรส/บุตร/บิดามารดา) **ไม่มี checkbox** — ใช้ตามปีภาษีล่าสุดเสมอ เพราะเป็นข้อเท็จจริงของครอบครัว ไม่ใช่ยอดเฉพาะปี
- Projection ใช้ปีภาษีล่าสุดที่มี config จริงเป็นฐาน (`useAvailableTaxYears()[0]`) กรองเฉพาะรายการที่ `use_in_projection=true`

### ผลลัพธ์
- การ์ดสรุป: net worth ปัจจุบัน / net worth ปลายปีที่ N / กระแสเงินสดสุทธิเฉลี่ยต่อเดือน (ตลอด N ปี)
- กราฟเส้น net worth ตลอด N ปี (`ProjectionNetWorthChart.tsx` — style เดียวกับ `NetWorthChart.tsx` ของ C4)
- ตาราง (`.table-scroll`/`.data-table` — เลื่อนแนวนอน + คอลัมน์แรกตรึงซ้ายบนมือถือ ตาม REQUIREMENTS §8.1): M ปีแรกรายเดือน (จัดกลุ่มตามปี), (N−M) ปีที่เหลือรายปี — คอลัมน์ รับเข้า/จ่ายออก/โยกเข้าสินทรัพย์/เงินต้นผ่อนหนี้/ดอกเบี้ยเงินกู้/กระแสเงินสดสุทธิ/Net worth สะสม
- Banner extrapolation ต่อปีที่ใช้ config ประมาณการ

### Golden case ตรวจสอบ (REQUIREMENTS §5.3) — ผ่าน
ปิดบัญชี ก.ค. 69, N=5, M=2, โหมดปีปฏิทิน → ปีที่ 1 (2569) ส.ค.-ธ.ค. (5 เดือน) รายเดือน, ปีที่ 2 (2570) เต็มปีรายเดือน, ปีที่ 3-5 (2571-2573) รายปี — ตรงสเปคทุกจุด ยืนยันตัวเลขภาษีถูกต้องด้วยมือ

## แก้บั๊ก take-home (`ratioCalculations.ts`, ค้างมาตั้งแต่ C5/C6)

`calculateAnalysisFigures` รับ parameter ใหม่ `estimatedTaxSatang: number | null` — คำนวณจาก `buildIncomeByTypeFromLegs` (จัดกลุ่ม legs 12 เดือนล่าสุดที่ใช้อยู่แล้วในหน้า `/analysis` ตาม 40(1)-(8)) ส่งเข้า `calculateTaxReturn` (C6) ตรงๆ โดยใช้:
- **Tax config**: ปีภาษีล่าสุดที่มีจริง (`useAvailableTaxYears()[0]`)
- **Header/ค่าลดหย่อน**: ที่ผู้ใช้เคยกรอกไว้ในหน้า `/tax` ปีนั้นจริง (ถ้ายังไม่เคยกรอกเลย ถือเป็น 0 ทุกช่อง — ยังดีกว่าไม่ประเมินภาษีเลย)
- `totalWithholding: 0` เสมอ (ใช้แค่ `finalTax` เป็นตัวประมาณภาษีที่ต้องจ่ายจริง ไม่สนใจยอดคืน/จ่ายเพิ่มที่ต้องพึ่งข้อมูล WHT ของช่วงเวลาที่ตรงกันเป๊ะ)

`monthlyTakeHome = (totalIncome − estimatedTaxSatang) / months` — ไม่มี tax config เลย → `estimatedTaxSatang = null` → fallback เป็นพฤติกรรมเดิม (pre-tax) พร้อม field ใหม่ `takeHomeIsAfterTax: boolean` ให้ UI แสดง caveat ต่างกัน

**ข้อจำกัดที่ทราบและยอมรับ**: ช่วงเวลาของ ratio (12 เดือนล่าสุดแบบ rolling) กับปีภาษี (ปฏิทิน) ไม่ตรงกันเป๊ะ — เป็นการประมาณ ไม่ใช่ภาษีที่ต้องจ่ายจริงเป๊ะ 100% แต่แม่นกว่ารายได้ก่อนหักภาษีมาก
