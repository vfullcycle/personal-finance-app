> พึ่งพา C1 (`SPEC-foundation.md`), C2 (`SPEC-auth-coa-accounts.md`), C3 (`SPEC-transactions-recurring.md`)

## ขอบเขต
หน้า `/accounts` แท็บ "ภาษี" → `/tax` — flow: ledger สะสมเงินได้ตามปีภาษี (พ.ศ.) → จำแนก 40(1)-(8) → หักค่าใช้จ่าย → หักค่าลดหย่อน → bracket ขั้นบันได เทียบมาตรา 48(2) → เทียบภาษีหัก ณ ที่จ่าย/ภ.ง.ด.94 → คืน/จ่ายเพิ่ม ตาม REQUIREMENTS §6

**ตัวเลขปีภาษี 2568/2569 ต้อง search จากกรมสรรพากรจริงตอน build (ห้ามใช้ความจำ)** — แหล่งอ้างอิงหลัก: [rd.go.th](https://www.rd.go.th), FlowAccount, K WEALTH (ดู CHANGELOG สำหรับลิงก์เต็ม) — **reconcile กับ ภ.ง.ด.90 ตัวจริงปีภาษี 2568 ที่วีส่งมาแล้ว ตรงทุกบรรทัดหลังแก้บั๊ก** (ดูหัวข้อ reconcile ด้านล่าง)

## Schema — config ภาษีแบบ versioned (migration 5 ไฟล์, additive)

| ตาราง | หน้าที่ |
|---|---|
| `tax_config_versions` | header ต่อ version: `tax_year`, `version_no`, `effective_from`, `note`, `retirement_combined_cap_satang` (เพดานรวม PVD/กบข./RMF/ประกันบำนาญ/ThaiESG/กอช.), `life_health_combined_cap_satang` (เพดานรวมประกันชีวิต+สุขภาพตนเอง), `section48_2_*` (threshold/rate/exempt) |
| `tax_brackets` | ขั้นบันได ต่อ version — `min/max_income_satang`, `rate_percent` |
| `tax_expense_rules` | หักค่าใช้จ่ายต่อประเภทเงินได้ 40(1)-(8) — `shared_group` (40(1)+40(2) แชร์เพดานเดียวกัน), `uses_category_table` (40(5)), `alt_rate_percent`/`alt_label` (40(6) ประกอบโรคศิลปะ/ประณีตศิลปกรรม ใช้ alt เดียวกัน) |
| `tax_rental_expense_rates` | อัตราเหมาค่าเช่า 40(5) แยกตามประเภททรัพย์สิน |
| `tax_deduction_items` | รายการลดหย่อนทั้งหมด generic (`calc_type`: fixed/per_dependent/user_amount, `retirement_group`/`life_health_group` เพดานรวม, `double_amount` สำหรับบริจาค 2 เท่า) |
| `v_tax_config_current` | view: version ล่าสุดต่อปีภาษี (⚠️ `select *` — เพิ่มคอลัมน์ใหม่ใน `tax_config_versions` ทีหลังต้อง `CREATE OR REPLACE VIEW` ใหม่เสมอ ไม่งั้นคอลัมน์ใหม่หายจาก view เงียบๆ — เจอบั๊กนี้จริงตอน reconcile) |
| `tax_returns` / `tax_return_deductions` / `tax_withholding_entries` | ข้อมูลผู้ใช้ต่อปีภาษี (RLS ปกติ) — header (คู่สมรส/บุตร/บิดามารดา/วิธีหักค่าใช้จ่ายที่เลือกได้/`pnd94_paid_satang`), ยอดลดหย่อนจริงต่อรายการ, log ใบหัก ณ ที่จ่าย |

### สิทธิ์แก้ config กลาง
`tax_config_versions` และตารางลูกเป็น shared reference data (เหมือน `account_types`) ทุกคนอ่านได้ แก้ได้เฉพาะ username `admin` — บังคับที่ RLS ผ่านฟังก์ชัน `is_admin()` (security definer เช็ค `profiles.username`) ไม่ใช่แค่ซ่อนปุ่มฝั่ง UI แก้ = สร้าง version ใหม่เสมอ (ไม่ overwrite) `tax_returns.config_version_id` snapshot ว่าตอนคำนวณใช้ version ไหน กันแก้ทีหลังแล้วเลขเก่าเปลี่ยนเงียบๆ ทุกคน (ไม่ใช่แค่ admin) พรีวิวผลกระทบต่อภาษีตัวเองได้ในแท็บ "ตั้งค่าภาษี" ก่อนบันทึกจริง

## Calculation engine (`src/features/tax/taxCalculations.ts`) — pure functions

1. `computeExpenseDeduction` — 40(1)+40(2) รวมเพดานเดียวกัน (50% ไม่เกิน 100,000) หักแล้วแบ่งคืนตามสัดส่วน gross เพื่อแสดงผลรายประเภท 40(4) หักไม่ได้ 40(5)/(6)/(7)/(8) เลือกวิธีได้ (เหมา/ตามจริง)
2. `computeDeductions` — เพดานกลุ่ม 2 กลุ่ม (เกษียณ 500,000, ประกันชีวิต+สุขภาพ 100,000 — สุขภาพเองมีเพดานย่อย 25,000 ซ้อนอยู่ในเพดานรวม) + **เพดานบริจาคแบบ cascade** ตรงตาม ภ.ง.ด.90 ข้อ11 บรรทัด 4-6 จริง: บริจาค 2 เท่า (การศึกษา/รพ.รัฐ) คำนวณ 10% จากฐานเต็มก่อน แล้วบริจาคทั่วไปคำนวณ 10% จากฐานที่ลดแล้ว (ไม่ใช่ฐานเดียวกันทั้งคู่)
3. `computeBracketTax` — ขั้นบันไดมาตรฐาน
4. `computeSection48_2` — เงินได้ 40(2)-(8) รวมกัน ≥ threshold (60,000) ต้องเทียบวิธี 0.5% ของเงินได้พึงประเมิน (ก่อนหักอะไรเลย) ยกเว้นถ้าคำนวณได้ ≤ exempt (5,000) จ่ายภาษีตัวที่สูงกว่า
5. `calculateTaxReturn` — ประกอบทุกขั้นตอน + เทียบภาษีหัก ณ ที่จ่าย + ภ.ง.ด.94 → คืน/จ่ายเพิ่ม

## Reconcile กับ ภ.ง.ด.90 ตัวจริง (26 ก.ค. 2569)

วีส่งไฟล์ ภ.ง.ด.90 ที่ยื่นจริงปีภาษี 2568 มาให้ตรวจ — ป้อนตัวเลขเดียวกันผ่านหน้าจอจริง ได้ผลตรงทุกบรรทัด (เงินได้สุทธิ 23,231.60, คืนภาษี 5,883.98) หลังแก้ 4 จุด:

- เพดานประกันชีวิต+สุขภาพ: แยกเป็น `life_insurance`/`health_insurance_self` (สุขภาพเพดานย่อย 25,000 ซ้อนในเพดานรวม 100,000)
- เพดานบริจาค cascade (ดูข้อ 2 ด้านบน)
- ลบ `donation_political_party` ออกจากรายการลดหย่อน — ไม่ใช่ตัวลดเงินได้สุทธิ เป็นการเจียดภาษีที่คำนวณเสร็จแล้วไปให้พรรค (revenue-neutral)
- บั๊ก `v_tax_config_current` (ดูหมายเหตุ ⚠️ ด้านบน) + ช่องกรอกเงินบาททุกช่องขาด `step="0.01"` ทำให้กรอกทศนิยม (เช่น 5,883.98) แล้ว browser บล็อกการ submit เงียบๆ (แก้ครบทุกช่องแล้ว)

## หน้าสรุปภาษี — เดินตามเลข "ข้อ"/"บรรทัด" ของ ภ.ง.ด.90 จริง
หลัง reconcile วีขอให้จัดหน้า `/tax` แท็บ "สรุปภาษี" ให้เทียบกับแบบฟอร์มจริงได้ทีละบรรทัด — จัดกลุ่มเงินได้ตาม "ข้อ" (40(1)+40(2)=ข้อ1, 40(3)=ข้อ2, ... 40(8)=ข้อ7) ข้อไหนไม่มีเงินได้ข้ามไปเหมือนแบบฟอร์มจริง ตามด้วย "ข้อ 11" (การคำนวณภาษี) กำกับเลขบรรทัด 1-25 ตรงตามแบบฟอร์ม (บรรทัด 3/5 clamp ที่ 0 กันแสดงติดลบตอนลดหย่อน/บริจาคเกินเงินได้ — ไม่มีทางเกิดในแบบฟอร์มจริง)

**Banner เตือนเพดานเต็ม** (กันงงว่าทำไมรายได้เพิ่มไม่ได้หักค่าใช้จ่ายเพิ่ม): เพดานรวม 40(1)+40(2), เพดานกลุ่มเกษียณ, เพดานกลุ่มประกันชีวิต+สุขภาพ

## Routes / UI
`/tax` (เข้าถึงผ่านแท็บ "ภาษี" ใน `/accounts` ไม่ใช่ nav หลัก — ตกลงเพิ่มระหว่างแชต) 5 แท็บ: **สรุปภาษี** (ตามข้อ/บรรทัดข้างบน), **ค่าลดหย่อน** (header คู่สมรส/บุตร/บิดามารดา + วิธีหักค่าใช้จ่ายที่เลือกได้ + รายการลดหย่อน generic จาก config), **ภาษีหัก ณ ที่จ่าย** (log WHT หลายใบ + ภ.ง.ด.94 ยอดเดียว), **What-if** (ลองเพิ่มยอดลดหย่อนรายการใดรายการหนึ่ง ดูภาษีประหยัดทันที), **ตั้งค่าภาษี** (ทุกคนพรีวิว, admin บันทึกจริงเป็น version ใหม่)

## Non-goals ของ C6 (ตัดออกชัดเจน หรือ backlog)
- final-tax election ของ 40(4) (ดอกเบี้ย/ปันผลเลือกไม่รวมคำนวณ) + เครดิตภาษีเงินปันผล + เครดิตภาษีต่างประเทศ
- ข้อ 8: ขายอสังหาริมทรัพย์ที่ไม่ใช่ทางการค้า (สูตรหักตามปีถือครองคนละแบบ)
- ข้อ 9: เงินได้จากการให้/รับ (เลือกเสียภาษี 5%), เขตพัฒนาพิเศษเฉพาะกิจ (ชายแดนใต้), ยื่นเพิ่มเติม/แก้แบบเดิม, เงินเพิ่ม (ค่าปรับยื่นช้า), คริปโต/โทเคนดิจิทัล
- PVD/กบข. หักก่อน/หลังค่าใช้จ่าย: ระบบหักเป็นก้อนเดียวหลังค่าใช้จ่ายเสมอ (ทางคณิตศาสตร์ผลเท่ากับวิธีจริงของกรมสรรพากร ยกเว้นเงินเดือนรวมต่ำกว่า ~200,000/ปี ที่เพดานหักค่าใช้จ่าย 100,000 ยังไม่เต็ม — ผลต่างเล็กน้อย)
- `ratioCalculations.ts` (C5) ยังไม่ดึงภาษีจริงมาหัก DSR/take-home (เฟส 1 ตามที่ตกลงไว้ตั้งแต่ต้น C6 ไม่ใช่ scope บังคับ) — backlog แยก
- ไม่เชื่อม e-filing กรมสรรพากรจริง เป็นเครื่องมือคำนวณ/วางแผนเท่านั้น
