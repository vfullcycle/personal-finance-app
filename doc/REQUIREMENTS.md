## 1. ภาพรวมและขอบเขต
เว็บแอปบริหารการเงินส่วนบุคคลแบบ **double-entry (บัญชีคู่)** ออกแบบเพื่อ **ผู้ใช้ทั่วไป** (ไม่ใช่เฉพาะเจ้าของ) รองรับหลายผู้ใช้ผ่านระบบ login แยกสมุดบัญชีต่อคน

ครอบคลุม 4 เสาหลัก:
1. บันทึกบัญชีละเอียด แยกประเภทรายรับ/รายจ่าย จัดหมวดหมู่
2. ออกงบการเงิน 3 รายการ (งบรายได้-ค่าใช้จ่าย, กระแสเงินสด, งบดุล) + net worth (ความมั่งคั่งสุทธิ)
3. วิเคราะห์ด้วย personal financial ratios + เครื่องมือช่วยตัดสินใจ
4. วางแผน: budget + projection ล่วงหน้า + คำนวณภาษีเงินได้บุคคลธรรมดาไทย

สกุลเงิน: **THB เท่านั้น**

## 3. โดเมนโมเดลแกน

### 3.1 ประเภทบัญชี (5)
asset (สินทรัพย์) · liability (หนี้สิน) · equity (ทุน) · income (รายได้) · expense (ค่าใช้จ่าย)

### 3.2 ตารางแกน
- `accounts` — บัญชีทั้งหมด มี type, ลำดับชั้น (หมวด/หมวดย่อย), ยอดยกมา, สถานะเปิด/ปิด, archive แทนลบ
  - income account เพิ่ม flag `taxable` + `income_type` (40(1)–(8)) เชื่อม tax engine
  - บัญชีประเภทสินทรัพย์/หนี้: รองรับ เงินสด/ธนาคาร/บัตรเครดิต/เงินกู้/การลงทุน/สินทรัพย์อื่น + วงเงินบัตร
- `transactions` — หัวรายการ (วันที่, payee, note)
- `transaction_legs` — ขาเดบิต/เครดิต (amount เป็นสตางค์, อ้าง account_id)

### 3.3 Invariant (บังคับที่ DB)
- ผลรวมทุก leg ของ transaction = 0 (balance)
- ห้ามลบ account ที่มี leg อ้างอยู่ (archive แทน)
- ยอดคงเหลือ/งบดุล/net worth = **view คำนวณสด** ไม่เก็บซ้ำ
- RLS: user เห็นเฉพาะแถวตัวเอง

### 3.4 Double-entry mapping (UX → เดบิต/เครดิต)
ผู้ใช้เห็นแค่ 3 ปุ่ม engine map ให้เบื้องหลัง:

| ปุ่มผู้ใช้ | เดบิต (Dr) | เครดิต (Cr) | ผลต่อ net worth |
|---|---|---|---|
| **เงินเข้า** | สินทรัพย์ (บัญชีที่รับ) | รายได้ (หมวด) | เพิ่ม |
| **เงินออก** | ค่าใช้จ่าย (หมวด) | สินทรัพย์ (บัญชีที่จ่าย) | ลด |
| เงินออกด้วยบัตร | ค่าใช้จ่าย (หมวด) | หนี้สิน (บัตร) | ลด |
| **โอน** ทั่วไป | บัญชีปลายทาง | บัญชีต้นทาง | คงที่ |
| โอนเข้าลงทุน | สินทรัพย์ลงทุน | สินทรัพย์เงินสด | คงที่ (เปลี่ยนรูป) |
| ผ่อนจ่ายหนี้ | หนี้สิน | สินทรัพย์ | คงที่ |

## 5. Budget + Projection (M7) — รายละเอียด

### 5.1 โครงสร้าง 2 ชั้น (บวกกัน)

**ชั้น A — งบประจำ (baseline)**
รายการสม่ำเสมอ ขับด้วยจำนวน/เดือนหรือ/ปี + **%growth ต่อปี**
เช่น เงินเดือน 50,000/เดือน +5%/ปี, ค่าอาหาร 8,000/เดือน +3%/ปี

**ชั้น B — แผนกำหนดการ (schedule / CF matrix)**
รายการผูกช่วงปีเฉพาะ แต่ละรายการมี field:

| field | ค่า |
|---|---|
| รายการ | ชื่อ เช่น เบี้ยประกันชีวิต |
| ประเภทบัญชี | อ้าง COA (กำหนดผลต่อ net worth) |
| ทิศทาง | จ่ายออก / รับเข้า / โยกเข้าสินทรัพย์ |
| ความถี่ | รายเดือน / ราย 3 เดือน / ราย 6 เดือน / รายปี / ครั้งเดียว (5 แบบ) |
| ปีเริ่ม – ปีจบ | ช่วงพ.ศ. |
| จำนวน | **ต่อครั้ง** (ไม่ใช่ยอดรวม) |
| growth/ปี | มีช่องให้ **default = 0%** |
| เดือนเริ่มงวด | (ตัวเลือกเพิ่มเติม) default = เดือนที่ปิดบัญชี — ใช้ระบุว่างวดตกเดือนไหนในจอรายเดือน |

หมายเหตุ: ทิศทาง "โยกเข้าสินทรัพย์" (เช่นลงทุน) กระแสเงินสดลดแต่ net worth คงที่ — ต่างจาก "จ่ายออก" ที่ทั้งคู่ลด นี่คือเหตุผลที่ต้องมี "ประเภทบัญชี" ต่อรายการ

### 5.2 กติกา projection
- user กำหนด: ระยะรวม **N** ปี, จำนวนปีที่แสดง**รายเดือน** = **M** ปีแรก
- แสดง M ปีแรกเป็นรายเดือน, (N−M) ปีถัดไปเป็นรายปี
- **โหมดตัดปี (switch):**
  - default = **ปีปฏิทิน** — ปีที่ 1 คือปีปฏิทินที่ปิดบัญชี (เป็น partial year ได้), นับต่อเป็นปีปฏิทินเต็ม
  - ทางเลือก = **เต็มปีจากวันปิด** (นับ 12 เดือนจริงจากวันปิด)
- projection แสดงทั้ง **กระแสเงินสด** และ **net worth** ล่วงหน้า (ไม่ใช่แค่ surplus)
- ฐานคำนวณ = ชั้น A + ชั้น B, เป็นตัวเลข **after-tax** (จึงจัด tax ไว้เฟส 2 ก่อน budget เฟส 3)

### 5.3 ตัวอย่างตรวจสอบ (golden case)
ปิดบัญชี ณ สิ้น ก.ค. 69, N=5, M=2, โหมดปีปฏิทิน:

| ปีที่ | พ.ศ. | ช่วง | แสดงผล |
|---|---|---|---|
| 1 | 2569 | ส.ค.–ธ.ค. 69 (5 เดือน) | รายเดือน |
| 2 | 2570 | ทั้งปี | รายเดือน |
| 3 | 2571 | ทั้งปี | รายปี |
| 4 | 2572 | ทั้งปี | รายปี |
| 5 | 2573 | ทั้งปี | รายปี |

→ รายเดือน ส.ค.69–ธ.ค.70, รายปี 71–73

### 5.4 variance
budget แบบ **fixed** ต่อหมวดต่อเดือน เทียบ actual, แจ้งเตือนใกล้/เกินงบ (ไม่มี envelope/rolling)

## 6. Thai PIT (M11) — รายละเอียด
Flow: ledger สะสมเงินได้ตามปีภาษี → จำแนกประเภทเงินได้ 40(1)–(8) → หักค่าใช้จ่าย → หักค่าลดหย่อน → คูณ bracket ขั้นบันได → ภาษีสุทธิ

- **Tax config เป็นตารางแยกตามปีภาษี (versioned)** — bracket + เพดานลดหย่อน ห้าม hardcode
- ค่าลดหย่อนครอบคลุม: ส่วนตัว/คู่สมรส/บุตร/บิดามารดา, ประกันชีวิต+สุขภาพ, PVD/กบข./RMF/SSF/ThaiESG/บำนาญ, ประกันสังคม, ดอกเบี้ยบ้าน, เงินบริจาค, มาตรการรัฐรายปี
- tracking ภาษีหัก ณ ที่จ่าย → สรุปคืน/จ่ายเพิ่ม
- what-if: ซื้อกองทุนลดหย่อนเพิ่มเท่าไรประหยัดภาษีเท่าไร
- 1 login = 1 ผู้เสียภาษี (ไม่รองรับยื่นรวม/แยก)
- **ตอน build: ต้อง search ตัวเลข bracket/เพดานปีภาษีล่าสุดจากกรมสรรพากรให้ตรง** (ห้ามใช้ความจำ)

## 7. Analysis (M8) — ratios + decision tools

| Ratio | สูตร | Benchmark |
|---|---|---|
| สภาพคล่องพื้นฐาน | สินทรัพย์สภาพคล่อง / ค่าใช้จ่ายต่อเดือน | 3–6 เท่า |
| อัตราการออม | เงินออม / รายได้รวม | ≥ 10% |
| ภาระหนี้ต่อรายได้ (DSR) | เงินผ่อนหนี้/เดือน ÷ รายได้/เดือน | ≤ 35–40% |
| ภาระที่อยู่อาศัย | ค่าที่อยู่อาศัย / รายได้รวม | ≤ 28–30% |
| หนี้ต่อสินทรัพย์ | หนี้สินรวม / สินทรัพย์รวม | < 50% |
| สินทรัพย์ลงทุน/net worth | สินทรัพย์ลงทุน / net worth | เพิ่มตามอายุ |

**Decision tools:**
- **ความสามารถซื้อของชิ้นใหญ่** = สภาพคล่องส่วนเกิน + discretionary cash flow/เดือน → "เก็บอีกกี่เดือนถึงซื้อได้โดยไม่แตะ emergency fund"
- **ความสามารถเป็นหนี้ (debt headroom)** = (DSR เพดาน × รายได้/เดือน) − ภาระผ่อนปัจจุบัน → ย้อนเป็นวงเงินกู้ได้ถ้าใส่ดอกเบี้ย+เทอม
- **Savings goals** = ตั้งเป้าออม + ติดตามความคืบหน้า
